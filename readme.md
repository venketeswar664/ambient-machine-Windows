## Project Overview

The Ambient Machine project implements a flexible pipeline architecture that allows for easy integration and orchestration of various data processing modules. The core components include:

- **Sensors**: Modules that collect data from external sources.
- **Thinkers**: Modules that process data using algorithms or machine learning models.
- **Actuators**: Modules that perform actions based on processed data.
- **Abstract Machine Class**: An extensible base class that defines the structure and behavior of all machines.
- **Pipelines**: Configurable sequences of machines that process data in a defined order.
- **Orchestrator**: The engine that manages the flow of data between machines and handles execution logic.

---

## Features

- **Modular Architecture**: Easily add, remove, or modify machines without affecting the overall system.
- **Dynamic Configuration**: Define pipelines and machine connections using JSON configurations.
- **Execution Modes**: Support for sequential, multithreaded, and multiprocessing execution.
- **Data Management**: Centralized data dictionary for managing inputs and outputs between machines.
- **Error Handling**: Input validation and comprehensive error logging.
- **Scalability**: Designed to handle multiple data streams and high-throughput processing.
- **Extensibility**: Create custom machines by subclassing the Machine base class.
- **Standalone Execution**: Machines can be run independently for testing and debugging.

## Installation

### Prerequisites

- **Python 3.10** or higher
- **Git** installed for version control (optional but recommended)
- **MongoDB** installed and accessible if you plan to use the database functionalities
- **NVIDIA GPU (Optional)**: If you have an NVIDIA GPU and want to run the project with GPU acceleration

### Clone the Repository

```bash
git clone https://github.com/yourusername/ambient-machine.git
cd ambient-machine
```

### Run the Setup Script

Make the setup script executable and run it to create a virtual environment and install dependencies.

```bash
chmod +x setup.sh
./setup.sh
```

### Activate the Virtual Environment

If the virtual environment is not already activated:

```bash
source venv/bin/activate
```

### Configure the Database

Edit `src/configs/database_config.json` with your MongoDB connection details.

```json
{
  "db_url": "mongodb://username:password@host:port/database_name",
  "project": "ambient_machine",
  "mode": "development"
}
```

## Usage

### Running the Application

With the virtual environment activated, run the main script:

```bash
python main.py
```

This will start the pipeline execution as defined in the configuration files.

### Developing a New Pipeline

To develop a new pipeline, follow these steps:

1. **Define Your Pipeline Configuration**: Create a new JSON file in the `src/configs/pipelines/` directory that defines your pipeline's machines, their configurations, inputs, outputs, and execution parameters.

2. **Create or Modify Machine Classes**: If you need new machines, create new machine classes in the appropriate directory under `src/core/` or modify existing ones.

3. **Update the Orchestrator**: Ensure that the orchestrator loads your new pipeline configuration and that any new machines are properly initialized.

4. **Run the Application**: Execute `python main.py` to run the orchestrator with your new pipeline.

## Architecture Overview

### Machine Base Class

- The `Machine` base class is an abstract class that defines the structure and behavior of all machines.
- Subclasses must implement the `process` method, where the core logic of the machine resides.
- Machines can execute multiple methods dynamically based on the configuration.
- Input data is validated, and errors are raised and logged if required inputs are missing.

**Key Components of the Machine Class:**

- **Initialization**: Loads configuration, initializes next machines, and sets up execution parameters.
- **Execution**: Manages the execution flow, including method execution and calling next machines.
- **Data Handling**: Validates and retrieves input data, sends processed data to the shared data dictionary.
- **Error Handling**: Logs and raises errors for missing inputs or method issues.

### Pipelines

- Pipelines are defined in JSON configuration files and consist of multiple machines connected via the `next_module` key.
- Each machine in the pipeline has its own configuration, including execution flags, input/output definitions, and the methods to execute.

**Example Pipeline Configuration:**

```json
{
  "pipeline_name": "main_pipeline",
  "start_machine": "get_cameras",
  "pipeline": {
    "get_cameras": {
      "name": "GetCameras",
      "module": "src/core/sensors/get_camera_doc.py",
      "config": {
        "collection": "src/database/schemas/cameras_schema.py",
        "fields": ["camera_address", "device_name", "zones", "process_skip_frame", "pipelines"]
      },
      "input": {},
      "output": {
        "cameras_dict": "dict"
      },
      "execute": {
        "method_names": ["process"],
        "flags": {
          "multiprocessing": false,
          "multithreading": false
        },
        "max_executions": 1
      },
      "next_module": ["camera_orchestrator"]
    },
    "camera_orchestrator": { ... },
    "detector": { ... },
    "zone_tracker": { ... }
  }
}
```

### Execution Flow

- The execution starts from the specified starting machine and follows the `next_module` connections.
- Machines can execute methods sequentially, in parallel using multiprocessing, or multithreading based on the execution flags.
- Execution counts can be controlled to prevent infinite loops, especially in circular pipelines.

## Creating Custom Machines

### Machine Structure

To create a new machine:

1. **Subclass the `Machine` Base Class**:

```python
from src.core.machine import Machine

class YourMachine(Machine):
    def __init__(self, machine_name, pipeline_config, data_dict=None, logger=None):
        super().__init__(machine_name, pipeline_config, data_dict, logger)
        config = self.config.get('config', {})
        # Your initialization code here

    def process(self, input_data):
        # Implement your processing logic here
        return processed_data
```

2. **Implement Required Methods**:

- **`process(self, input_data)`**: Core processing logic.
- **Optional**: Override `get_data`, `send_data`, `on_start`, `on_finish` if needed.

3. **Define Configuration in the Pipeline**:

```json
{
  "your_machine": {
    "name": "YourMachine",
    "module": "src/core/your_machine.py",
    "config": {
      // Your machine-specific configuration
    },
    "input": {
      // Input fields (if any)
    },
    "output": {
      // Output fields
    },
    "execute": {
      "method_names": ["process", "another_method"],  // Methods to execute
      "flags": {
        "multiprocessing": false,
        "multithreading": false
      },
      "max_executions": 1
    },
    "next_module": ["next_machine_name"]
  }
}
```

4. **Input Validation**:

- Ensure that your `get_data` method checks for missing input keys and raises errors while logging them.

5. **Error Handling and Logging**:

- Use the provided `logger` to log important events, errors, and debug information.

### Standalone Execution

- Each machine can be run independently for testing or debugging.
- Include an `if __name__ == "__main__":` block in your machine class file.

```python
if __name__ == "__main__":
    import json
    from src.utils.logger import Logger

    # Load machine-specific configuration
    with open('path/to/your_machine_config.json', 'r') as f:
        pipeline_config = json.load(f)

    # Initialize the logger
    logger = Logger(log_name='your_machine', log_dir='logs', verbose=True)

    # Initialize the data dictionary
    data_dict = {}

    # Create an instance of your machine
    machine_name = 'your_machine'
    your_machine = YourMachine(
        machine_name=machine_name,
        pipeline_config=pipeline_config,
        data_dict=data_dict,
        logger=logger
    )

    # Execute your machine
    your_machine.execute()
```

- Create a separate configuration file for standalone execution if needed.

## Troubleshooting

- **Missing Input Data**:

  - **Error**: `ValueError: Missing required input data for keys: [...] in machine ...`
  - **Solution**: Ensure that all required input data is provided to the machine via `data_dict`.

- **Method Not Found**:

  - **Error**: `AttributeError: Method '...' not found in ...`
  - **Solution**: Check that the methods specified in `method_names` exist in your machine class.

- **ModuleNotFoundError**:

  - Ensure that the `module` path in your configuration is correct and that the module can be imported.

- **Infinite Loops**:

  - Use the `max_executions` parameter to control the number of times a machine can be executed to prevent infinite loops.

- **Logging Issues**:

  - Verify that the `logger` is properly initialized and passed to your machine classes.
